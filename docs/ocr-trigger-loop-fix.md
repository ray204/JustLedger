# OCR 去重、弹窗与分类修复

## 自动识别流程

外部页面变化 → 页面历史预检 → 本地 OCR → AI 优先识别（未配置或三次请求仍失败时使用规则）→ 多标识匹配 → 已识别账单静默返回；新账单进入核对。

页面预检只是节省截图和模型调用的优化。识别后的去重不依赖页面结构，发生在创建账单、回执和编辑器之前。手动背部双击绕过去重静默；确定命中时直接打开原账单编辑，不生成另一条待核对草稿。

## 多组标识

| 标识 | 组成与范围 |
| --- | --- |
| 订单号 | 来源平台 + 订单号 |
| 支付流水号 | 支付机构 + 交易/支付流水号；只有明确的微信/支付宝标签或机构自身 App 能跨 App 匹配 |
| 商户订单号 | 来源平台 + 商户 + 商户单号 |
| 银行流水号 | 来源平台 + 银行流水号 |
| 退款流水号 | 来源平台 + 退款单号；原支付/订单号不能代替退款号 |
| 商品组合 | 同一来源、账本、收支类型、币种 + 精确到秒的时间 + 金额 + 商户 + 商品 |
| 账户组合 | 同一来源、账本、收支类型、币种 + 精确到秒的时间 + 金额 + 商户 + 具体付款账户 |

任一可靠标识命中即可匹配。相同类型的标识明确冲突、一个页面出现同类多个不同编号，或不同标识命中多个独立账单时，保留核对。组合键是保守的高置信推断，不是支付机构提供的唯一凭据；仅有金额、分钟时间、泛化商户或“微信/余额”等账户名不足以判断。

编号从有标签的原文提取，支持分组数字；模型输出的内部标识不可信，不直接入库。标识按类型和来源隔离，取餐码不作订单号。识别号匹配时允许模型误读原价/实付价，保留已确认金额。成功匹配后补充内部标识、缺失的商品等信息及机器生成的占位信息，已有金额、时间和用户明确设置的分类、备注等字段不被改写，也不新增回执。标识存于本机账单扩展字段，界面不展示内部字段；无需数据库破坏性迁移。旧账单继续兼容已有 transactionId、refundId 和用户确认的关联记录。

## 模糊候选直接展示

编辑页直接显示最多五条最接近的疑似记录，包括商户、金额、精确到秒的时间和渠道；无候选不显示“可能已有记录”，也不展示无效的补充入口。

- 同币种、同账本、同收支类型、金额一致，时间相差不超过一分钟时可以提示核对。
- 银行、短信、支付 App 记时不同，放宽到五分钟时需同商户或同一具体付款账户支持。
- 已知商户、商品或编号冲突的排除；退款没有同一退款编号时不拿同额记录作候选。
- 金额“差不多”不足以判断，不使用百分比或任意金额容差。这样不会把优惠前价格或附近另一笔消费自动并入。
- 只有用户点选并确认才合并模糊候选；另存新账单仍可用。确定命中的路径不会再进入这个选择过程。

## 防止弹窗循环

- 过滤 JustLedger 自身事件，取消待执行的防抖；读取同一个外部窗口，拒绝来源不一致或延迟后切换的页面。
- 手动与自动识别共用尝试记录，在截图/弹窗之前登记。成功、失败不因三秒倒计时而自动重试。
- 进程内保存最近 128 个页面指纹；成功页面的持久历史另存 MMKV，仅存摘要，应用重启后仍可预检。旧成功 OCR 记录会导入历史。
- 任务、横幅、编辑器、确认回执及嵌套窗口分别登记生命周期，全部退出才释放自动识别保护。
- 自动识别已知订单无进度、成功或失败弹窗；手动保留反馈。仅手动成功后提供“记住页面”。

## 编辑页与分类

金额与类型同行；重复账单使用简短圆角提示和“补充原账单”入口。商户、商品、分类、时间、账户使用紧凑行，扩展详情默认折叠。存在补充入口时，新增按钮标为“另存新账单”。

独立账本首次缺少分类时补齐 22 个支出、6 个收入分类，并复用分类图标。保留已有自定义分类；初始化后不重新补回用户主动删除的分类。AI 在同一次订单识别中获得本地分类候选，无须额外分类请求。已确认账单不会被批量重分类，可以在编辑页自行调整。

## 验证方式

服务端 JUnit 覆盖页面生命周期、持久历史、独立标识、跨 App 机构范围、秒级组合、退款隔离、标识冲突、手动绕过及分类初始化。

`tests/device/ocr_silent_repeat.py` 在真机服务中使用本地模型替身，验证模型调用后的静默判重、原价误读、别名记忆、多账单歧义、分类候选与手动预览。用带标记的测试记录，完成后清理并恢复手机模型设置。真实订单另做 AI 回放与手机编辑器检查；具体执行结果记录在本轮交付说明，测试脚本存在不代表已通过。
