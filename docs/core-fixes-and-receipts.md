# 核心修复与自动入账确认

本次修改基于 `feat/clear-ledger-ui` 工作区，保留已有 JustLedger 改名与界面设计。代码审查基线见 [核心机制审查](core-mechanisms-review.md)。本文件记录实现状态；2026-10-24 已完成 Android 编译及部分真机验证，详见 [真机验证记录](device-validation-2026-10-24.md)。

## 自动入账后的交互

1. 可信账单自动保存到 JustLedger 本地账本；账单与待知悉记录在同一个 Room 事务中提交。
2. 弹窗显示“这一笔已自动计入”，列出金额、类型、商户、账户、渠道、时间和账本。
3. 没有倒计时；返回键、点外部、下滑均不能取消。只有点击“知道了”，并且服务端保存确认成功，才结束该笔待知悉状态。确认不再次记账。
4. 多笔按持久化顺序逐笔展示。应用或服务重启、宿主窗口销毁，都不会自动确认；恢复运行后继续展示。
5. 展示期间账单更新，会重新显示最新内容；旧内容的确认请求返回冲突，不能确认用户尚未看到的修改。
6. 通知栏保留待确认数量，可点击进入应用。锁屏时不展示交易详情。无悬浮窗权限时，待确认状态仍保存在数据库，回到首页展示；通知权限被拒绝时也保留数据。
7. 保存失败不会显示成功。疑似重复、无法关联原单的退款、AI 识别结果进入人工核对，不先计入统计。

“已计入”指本地账本提交成功，不代表钱迹等外部软件同步成功。系统强行停止进程、未授予权限、厂商后台限制时，不能保证立即跨应用弹窗；持久化的是待知悉状态，不是强制窗口常驻系统的能力。历史账单不会在升级后批量补弹。提醒保存的是已提交事件，后续删除账单不会自动表示用户已经知悉该历史入账事件。

## 修复内容与边界

| 机制 | 本次实现 | 尚需验证或继续适配 |
| --- | --- | --- |
| 通知与短信采集 | 通知重绑定指向实际服务；使用 CharSequence；通知使用事件标识区分同文案不同交易；通知和短信先写原子文件，再用 WorkManager 投递，重启恢复 | 各银行、微信和支付宝的当前版本格式仍依赖下载规则；不能把白名单当成已验证支持清单 |
| Hook | 统一缓存键，原子占用；系统通知优先发布事件，方法不存在时回退入队 Hook；已发布事件与普通通知监听使用一致事件标识 | 厂商 Hook 签名、系统权限需真机验证；外部宿主 Hook 尚无完整持久化发送队列；备用入队事件与普通监听不一定有共同 ID |
| 防重与转账 | 同金额和时间不再直接证明重复；交易号、所属平台、账本、币种、账户参与判断；缺少凭据的疑似重复进入人工核对。自动转账需要明确交易关联及两个不同的自有账户 | 微信与银行通知通常没有共同交易号，因此不能保证全自动跨渠道合并。旧规则未输出新 ID 字段时，自动合并率会下降，这是保守处理 |
| 退款 | 独立退款号、原交易号和本地原单关联；区分退款处理中与到账；累计退款不得超过原支出；相同原订单的多次等额退款不能仅按原订单去重 | 未匹配原单需用户选择；选择器当前返回最近 500 条支出。退款规则仍需按渠道样本补齐 |
| 原支出保护 | 已关联有效退款时，限制修改类型、账本、币种、统计状态；原支出金额不得小于累计退款；删除原支出前需处理关联退款 | Room 路由集成与编辑器提示需要真机验收 |
| 合并撤销 | 保存合并前双方快照，事务恢复；只允许从最近合并起撤销；父单后续有修改则拒绝覆盖；同步刷新待确认内容 | 无快照的历史记录需人工处理；不自动撤销外部软件中已同步的记录 |
| OCR | 指纹保留金额和订单数字，不再截断前 300 字；按应用与页面区分，避免永久屏蔽相同页面；使用实际结构指纹，移除对 com.android 前缀的一刀切过滤；截图超时保护、前台页面校验、JPEG MIME 修正、识别串行；视觉识别遵循 AI 开关 | 原生 OCR 未暴露可用的置信度门槛；金额误读率、长截图、设备性能仍需真实截图集评测。新安装默认保活，已有用户设置保留 |
| 识别与存储 | 先规则，规则未识别才考虑可选 AI；手动触发也不绕过 AI 总开关；自动保存、归并与入账提醒放在事务内；入库后的同来源重放返回已提交记录 | 原始信息先存储；不匹配规则的消息可供排查，但不会自动变成有效账单。AI 识别结果要求人工核对 |
| 外部退款同步 | 原单未找到明确报错；退款查找不再限于 10 天；无可靠外部原单关联时不把退款降级成普通收入同步 | 本地原单 ID 与钱迹 ID 尚无完整双向映射，不能保证退款自动同步；本地记账不受影响 |

没有新增微信、支付宝或银行官方资金接口。也没有宣称所有渠道、所有机型都已有效。

## 数据迁移

Room 数据库从 21 升级到 22，增加交易凭据、退款关系、核对原因、合并快照字段以及 `BillNoticeModel`。实体默认值与迁移 SQL 保持一致。旧账单保留，新字段使用安全默认值，不自动生成旧账单提醒。完整 Room schema 校验仍需 Android 构建环境。

## 真机验收清单

- 新安装和从数据库 21 升级：历史账单完整，新账单保存一次，弹窗金额正确。
- 一笔自动入账：等候超过旧提示倒计时、点外部、返回、下滑都不确认；点击“知道了”后关闭，重启不再弹该笔。
- 连续三笔：逐笔展示，确认一笔不会跳过其他笔。
- 未确认时杀进程、旋转、切应用、锁屏再解锁：待确认数据保留，恢复后继续展示。
- 关闭通知/悬浮窗权限：不崩溃，首页恢复待确认队列；重新授权后恢复通知。
- 入库失败、确认接口失败、确认时账单更新：不能误报成功或丢失待确认状态。
- 微信绑卡付款与银行短信/通知、同额两笔付款、延迟银行通知：有凭据才自动归并，无凭据保留核对。
- 全额/部分/多次等额退款、重复退款通知、处理中通知、超过可退金额、原单修改与删除：验证累计金额、状态和错误提示。
- OCR 不同金额但相同布局、超过 300 字的订单差异、农行页面、快速切页、截图失败：检查是否漏识别、误合并或卡住。
- 钱迹同步失败和退款外部原单缺失：本地记录保留，不能显示为外部同步成功。
