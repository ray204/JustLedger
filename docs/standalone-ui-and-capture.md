# JustLedger 独立账本与界面验证（2026-10-24）

## 采集方式

当前默认采用不依赖 Xposed 的采集路径。内部的 `Ocr` 模式名称并不代表只能截图：通知监听、银行短信接收和屏幕 OCR 是不同入口。通知或短信包含足够的交易信息，并匹配渠道规则时，可以自动识别付款；屏幕识别用于补充。缺少权限、规则或完整交易信息时，不能承诺自动识别成功。

本轮没有读取真实支付页面或进行真实付款。当前测试手机尚未配置真实渠道规则，也未完成通知监听、短信和 OCR 无障碍授权，因此真实微信、支付宝、银行采集及跨渠道去重仍待验证。

## 产品与界面变化

- 固定使用 JustLedger 本地账本，移除外部记账软件选择、同步入口及保存后的外部同步；禁用自动 HTTP 账单推送，保留备份功能。
- 引导直接进入采集权限与后台运行设置，跳过目标记账软件和 AI 配置；首页缺少采集权限时提示继续设置。是否有有效渠道规则仍需单独检查，权限不等于识别已就绪。
- 账单列表增加分类环形图和收支柱状图；币种独立切换，未核对及不计统计的账单不计入图表。净支出扣除退款，分类与趋势展示退款前支出，并单独标注退款，避免混淆。
- 入账提醒仅保留金额、商户、账户、时间。多笔使用左右滑动卡片，滑动不确认；“确认本笔”只处理当前一笔，剩余卡片在同一弹窗内更新。
- “去修改”进入 App 编辑当前账单，保存或取消后恢复原卡片；编辑本身不算确认。编辑器缩小账本标题，移除大封面和空规则信息。
- 首页金额、账单图表在入账及编辑后实时更新；商户名称优先显示，列表金额固定两位小数。
- 更换启动图标、简化设置文案，保留必要的开源致谢。底层兼容类和历史字段尚未整体删除。

## 真机验证

设备：Xiaomi 15 / Android 16，ADB 覆盖安装 debug APK。通过 UIAutomator 操作实际界面，配合手机本地 HTTP 接口检查持久化结果；测试账单均为明确标记的合成样本。

| 场景 | 结果 |
| --- | --- |
| 三笔提醒左右切换 | 卡片切换，不提前确认；中间一笔确认后仅删除该待确认项 |
| 去修改金额再返回 | 修改持久化、金额更新，队列保持；后续复测取消编辑返回原来的第二张卡片 |
| 返回键关闭提醒 | 不关闭，待确认记录保留 |
| 桌面悬浮窗 → 去修改 | 开启悬浮窗权限后可进入 App 编辑，取消后恢复提醒，明确确认后关闭 |
| 月统计与实时更新 | CNY 支出 60、退款 5、收入 100 得到净支出 55；编辑金额后首页与图表自动更新 |
| 币种与排除项 | USD 20 独立展示；待核对且不计统计的 999 不进入图表和月统计 |
| 图表切换 | 分类图与柱状图可切换，退款口径可见 |
| 新引导 | 采集权限 → 后台设置 → 完成；不再经过外部记账软件和 AI 页 |
| 数据清理 | 仅删除本轮 10 笔标记样本，先删关联退款；未清空数据库。待确认 0，月收入与支出恢复 0 |

`:server:testDebugUnitTest` 运行 49 个既有单元测试，失败和错误均为 0；`:app:assembleDebug` 成功并覆盖安装。没有把接口注入测试当作真实渠道采集通过的证据。

本地证据位于 `.local/android/standalone-ui/`：`receipt-final.png`、`editor-final.png`、`chart-pie-final.png`、`chart-bars-final.png`、`chart-usd-bars.png`。构建与测试日志位于 `.local/android/logs/standalone-ui-checks.log`、`standalone-ui-final-build.log`。截图含验证样本，不代表真实消费。
